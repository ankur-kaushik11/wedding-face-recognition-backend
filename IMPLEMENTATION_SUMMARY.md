### Database Schema

#### Users Table
```sql
id           UUID PRIMARY KEY
role         ENUM ('admin', 'user')
last_login   TIMESTAMP WITH TIMEZONE
created_at   TIMESTAMP WITH TIMEZONE
```

#### Photos Table
```sql
id              UUID PRIMARY KEY
drive_file_id   VARCHAR (indexed, supports multiple faces per photo)
drive_url       VARCHAR
day_name        VARCHAR (indexed)
face_embedding  FLOAT[] (128-dimensional array)
indexed_at      TIMESTAMP WITH TIMEZONE (indexed)
```

#### ActivityLogs Table
```sql
id           UUID PRIMARY KEY
user_id      UUID FOREIGN KEY -> users.id (CASCADE DELETE)
action       ENUM ('login', 'face_scan', 'download')
photo_count  INTEGER (nullable)
timestamp    TIMESTAMP WITH TIMEZONE (indexed)
```

### Key Design Decisions

1. **Multiple Faces Per Photo**: Removed unique constraint on `drive_file_id` to allow storing multiple face embeddings per photo (one record per detected face).

2. **Thumbnail Processing**: Downloads thumbnails instead of full images during indexing to save bandwidth and improve speed.

3. **Cosine Similarity**: Uses cosine similarity for face matching with configurable threshold (default 0.6).

4. **Stateless Authentication**: JWT tokens contain user ID and role, no server-side session storage needed.

5. **Activity Logging**: Every user action is logged to the database for analytics and audit trails.

6. **Force Reindex**: Admin can choose to reindex only new photos or force reindex all photos.

7. **Rate Limiting**: Face scan endpoint limited to 5 requests per minute per IP address.
